    6. Interfaces

    Una interfaz es una estructura que define prototipos de métodos. Una clase que implementa una interfaz debe definir el código para todos los métodos de la interfaz.

    6.1. El árbol de scripts

    6.2. Una primera interfaz

    Definimos una interfaz [IExample] en un script [IExample.php]. En este mismo script, definimos dos clases que implementan la interfaz [IExample]:

    
<?php
 
// strict adherence to function parameter types
declare(strict_types=1);
 
// namespace
namespace Exemples;
 
// an interface
interface IExemple {
    // interface methods
    public function ajouter(int $i, int $j): int;
    public function soustraire(int $i, int $j): int;
}
 
// implementation 1 of the IExemple interface
class Classe1 implements IExemple {
    public function ajouter(int $a, int $b): int {
        return $a + $b + 10;
    }
 
    public function soustraire(int $a, int $b): int {
        return $a - $b + 20;
    }
 
}
 
// implementation 2 of the IExemple interface
class Classe2 implements IExemple {
    public function ajouter(int $a, int $b) : int{
        return $a + $b + 100;
    }
 
    public function soustraire(int $a, int $b) : int {
        return $a - $b + 200;
    }
 
}

    Comentarios

    • líneas 10-14: La interfaz IExample define dos métodos: la función add (línea 12) y la función subtract (línea 13). La interfaz no define el código de estos métodos. Serán las clases que implementen la interfaz las que lo hagan;
    • línea 17: La clase Class1 implementa la interfaz IExample. Por lo tanto, define el código para el método add (línea 18) y el método subtract (línea 22);
    • líneas 29–38: lo mismo ocurre con la clase Class2;

    Utilizamos la interfaz [IExample] en el siguiente script [interfaces-01.php]:

    
<?php
 
require_once "IExemple.php";
use \Exemples\Classe1;
use \Exemples\Classe2;
use \Exemples\IExemple;
 
// function
function calculer(int $a, int $b, IExemple $interface) : void {
  print $interface->ajouter($a, $b)."\n";
  print $interface->soustraire($a, $b)."\n";
}
 
// ------------------- hand
// creation of 2 objects of type Class1 and Class2
$c1 = new Classe1();
$c2 = new Classe2();
// call the calculate function
calculer(4, 3, $c1);
calculer(14, 13, $c2);

    Comentarios

    • líneas 3-6: inclusión y definición de las clases e interfaces utilizadas por el script;
    • línea 3: en lugar de la instrucción include, aquí hemos utilizado la instrucción require_once. La instrucción include incorpora un archivo en el script actual aunque ya se haya incluido anteriormente, mientras que la instrucción require_once solo lo incluye una vez. Por lo tanto, a la hora de incluir código, preferimos la instrucción require_once;
    • Líneas 9–12: Definimos una función;
    • Línea 9: Aquí declaramos los tipos de los tres parámetros. Si, en tiempo de ejecución, el parámetro real no es del tipo esperado, se lanza un error. El tercer parámetro es de tipo [IExample]. Esto significa que el parámetro real debe ser una instancia de una clase que implemente la interfaz [IExample]; en nuestro ejemplo, esto significa una instancia de las clases [Class1] o [Class2];
    • Líneas 10–11: Utilizamos los métodos [add, subtract] de la interfaz [IExample];
    • línea 19: el tercer parámetro real es de tipo [Class1], que es compatible con el tipo [IExample] del tercer parámetro formal de la función;
    • línea 20: lo mismo ocurre con la clase [Class2];

    6.3. Derivar una interfaz

    Del mismo modo que una clase hija puede extender una clase padre, una interfaz hija puede extender una interfaz padre.

    Consideremos la interfaz [IExample2] definida en el archivo [IExample2.php]:

    
<?php
 
// strict adherence to function parameter types
declare(strict_types=1);
// namespace
namespace Exemples;
 
// interface definition IExemple included
require_once __DIR__."/IExemple.php";
 
// an interface derived from IExemple
interface IExemple2 extends IExemple {
    // the interface method
    public function multiplier(int $i, int $j): int;
}
 
// implementation of IExemple2 interface
class Classe3 extends Classe2 implements IExemple2 {
   
    public function multiplier(int $a, int $b): int {
        return $a * $b;
    }
 
}

    Comentarios

    • línea 6: la interfaz [IExample2] estará en el mismo espacio de nombres que la interfaz [Iexample];
    • línea 9: se incluye el archivo de definición de la interfaz [Iexample];
    • líneas 12-15: definen la interfaz [IExample2], que extiende (hereda de) la interfaz [IExample] y le añade un nuevo método (línea 14);
    • líneas 18–24: la clase [Class3] extiende la clase [Class2]. Dado que [Class2] implementa la interfaz [IExample], [Class3] también la implementará. De hecho, [Class3] hereda todos los métodos públicos y protegidos de la clase [Class2], incluidos los métodos add y subtract. Además, especificamos que [Class3] implementa la interfaz [IExample2]. Como tal, también debe implementar el método multiply, algo que [Class2] no hace. Esto es lo que hacen las líneas 20–22;

    La interfaz [IExample2] es utilizada por el siguiente script [interfaces-02]:

    
<?php
 
// strict adherence to function parameter types
declare(strict_types=1);
 
// inclusion and qualification of classes and interfaces required by the script
require_once __DIR__."/Iexemple2.php";
use \Exemples\IExemple2;
use \Exemples\Classe3;
 
// function
function calculer(int $a, int $b, IExemple2 $interface) {
    print $interface->ajouter($a, $b) . "\n";
    print $interface->soustraire($a, $b) . "\n";
    print $interface->multiplier($a, $b) . "\n";
}
 
// ------------------- hand
// creation of 1 Class3 object implementing IExemple2
$c3 = new Classe3();
// call the calculate function
calculer(4, 3, $c3);

    Comentarios

    • línea 12: el tercer parámetro de la función [calculate] es de tipo [IExample2];
    • líneas 13-15: se utilizan los tres métodos de la interfaz [IExample2];
    • línea 22: se llama a la función [calculate] con un objeto de tipo [IExample2] como tercer parámetro (línea 20);

    6.4. Pasar una interfaz como parámetro de función

    En la sección anterior vimos que, cuando el tipo esperado para un parámetro de función es una clase, el parámetro real puede ser un objeto del tipo esperado o de un tipo derivado. Lo mismo se aplica a las interfaces, como se muestra en el siguiente script [interfaces-03.php]:

    
<?php
 
// strict adherence to function parameter types
declare(strict_types=1);
 
// inclusion and qualification of classes and interfaces required by the script
require_once __DIR__."/IExemple.php";
use \Exemples\IExemple;
require_once __DIR__."/IExemple2.php";
use \Exemples\Classe3;
 
// function
function calculer(int $a, int $b, IExemple $interface) {
  print $interface->ajouter($a, $b) . "\n";
  print $interface->soustraire($a, $b) . "\n";
}
 
// ------------------- hand
// creation of 1 object of type Class3 which implements IExemple2 and therefore IExemple
$c3 = new Classe3();
// call the calculate function
calculer(4, 3, $c3);

    Comentarios

    • línea 13: la función [calculate] espera un tipo [IExample] como tercer parámetro. Esto significa que el tipo del parámetro real puede ser [IExample] o un tipo derivado;
    • línea 20: instanciamos un objeto $c3 de tipo [Class3], una clase que implementa la interfaz [IExample2], la cual a su vez extiende la interfaz [IExample]. Así que, en definitiva, $c3 implementa la interfaz [IExample];
    • línea 22: llamamos a la función [calculate] con un objeto $c3 de tipo [Class3] como tercer parámetro. Gracias a la interacción entre la herencia de clases y las implementaciones, hemos visto que el objeto $c3 implementa el tipo [IExample]. Por lo tanto, podemos utilizarlo como tercer parámetro;
