    10. Aplicaciones en capas

    10.1. Introducción

    Ahora exploraremos cómo estructurar una aplicación PHP en capas:

    En este diagrama, la capa de la izquierda inicia el uso de la capa de la derecha. Las funciones de las capas son las siguientes:

    • [1]: La capa denominada [DAO] (Data Access Objects) gestiona las interacciones con los almacenes de datos externos [4] (archivos, bases de datos, servicios web, etc.). Esta capa se denomina a veces [DAL] (Capa de Acceso a Datos), un término que describe mejor su función. Esta capa puede leer datos [3] o escribir datos [2]. Es invocada por la capa [business] [6] y le devuelve los resultados [7];
    • [5]: una capa denominada [business] que contiene procedimientos «de negocio», a los que se les proporcionan todos los datos que necesitan. Por lo general, esta es la capa más estable de un proyecto, ya que no depende de cómo se obtienen los datos. Los datos provienen de dos fuentes:
      • [9]: datos proporcionados por el script PHP;
      • [6,7]: datos solicitados a la capa [DAO].
    • [8]: el script principal actúa como coordinador. En una aplicación de consola, se encargará de:
      • crea las capas [business] y [DAO];
      • ejecuta el algoritmo de la aplicación. Este algoritmo actúa como un coordinador: no contiene lógica «de negocio» ni código de acceso a datos. El script principal simplemente llama a los procedimientos de la capa [business] [9]. Ignora por completo la capa [DAO] y los datos externos. Puede proporcionar datos a la capa [business] [9]. En una aplicación de consola, estos datos pueden proceder de archivos de configuración o del usuario del script. Recibe resultados [10] de la capa [business]. Es posible que necesite almacenar ciertos resultados: para ello, vuelve a utilizar los procedimientos de la capa [business], que a su vez se dirigirá a la capa [DAO] para realizar la tarea;
      • entre los resultados, el script principal puede recibir excepciones. Su función es gestionar las excepciones que se propagan desde todas las capas;

    Esta arquitectura en capas está diseñada para facilitar la evolución de la aplicación. Con este fin, cada capa implementa una interfaz. Supongamos que:

    • la capa [DAO] está implementada por una clase [DAO] que implementa una interfaz [IDao];
    • la capa [business] está implementada por una clase [Business] que implementa una interfaz [IBusiness];

    Los procedimientos de la capa [business] utilizarán entonces la interfaz [IDao] en lugar de la clase [Dao]. Esto permite actualizar la capa [Dao] sin afectar a la capa [Business]. Supongamos que, en la versión 1, la capa [Dao1] utiliza datos de una base de datos. Tras una actualización, estos datos ahora los proporciona un servicio web en la versión 2, [Dao2]. Nos aseguraremos de que tanto la clase [Dao1] como la [Dao2] implementen la misma interfaz [IDao] y lancen las mismas excepciones. Si esto se verifica, la capa [Business] que trabaja con la interfaz [IDao] permanecerá sin cambios;

    El mismo razonamiento se aplica a la capa [Business].

    10.2. Objetos intercambiados entre capas

    Normalmente, las capas intercambian diversos objetos. En este caso, intercambiarán la siguiente clase [Person.php]:

    
<?php
 
// a person
class Personne {
  // identifier
  private $id;
 
  // manufacturer
  public function __construct(int $id) {
    $this->id = $id;
  }
 
  // toString
  public function __toString(): string {
    return "[Personne($this->id)]";
  }
 
}

    Comentarios

    • línea 6: la clase Person tiene un único atributo, su identificador [$id]. Supondremos que este identifica a una persona única en un almacén de datos;
    • líneas 9-11: el constructor que nos permite crear un objeto [Person] utilizando su ID;
    • líneas 14-16: el método [__toString] que muestra el identificador de la persona;

    10.3. Capa [DAO]

    La interfaz [IDao] implementada por la capa [dao, 1] es la siguiente [IDao.php]:

    
<?php
 
 
// layer [dao] ------------------------
interface IDao {
 
  // recovery of a person from an external warehouse
  // pass the person's login
  public function get(int $id): Personne;
 
  // saving a person in an external warehouse
  public function save(Personne $p): void;
}

    Esta interfaz es implementada por la siguiente clase [Dao1] [Dao1.php]:

    
<?php
 
class Dao1 implements IDao {
 
  // saving a person in an external warehouse
  public function save(Personne $p): void {
    print "[Dao1] : Sauvegarde de la personne $p en base de données [locale]\n";
  }
 
  // recovery of a person from an external warehouse
  public function get(int $id): Personne {
    print "[Dao1] : Récupération de la personne d'identité ($id) en base de données [locale]\n";
    return new Personne($id);
  }
 
}

    Comentarios

    • La clase no interactúa con un almacén de datos. Simplemente mostramos mensajes para seguir la ejecución del código (líneas 7 y 12);
    • Línea 13: Devolvemos una persona con el ID pasado como parámetro al método (línea 11);

    También implementamos la interfaz [IDao] con la siguiente clase [Dao2] [Dao2.php]:

    
<?php
 
class Dao2 implements IDao {
 
  // saving a person in an external warehouse
  public function save(Personne $p): void {
    print "[Dao2] : Sauvegarde de la personne $p en base de données [distante]\n";
  }
 
  // recovery of a person from an external warehouse
  public function get(int $id): Personne {
    print "[Dao2] : Récupération de la personne d'identité ($id) en base de données [distante]\n";
    return new Personne($id);
  }
 
}

    La clase [Dao2] es similar a la clase [Dao1], salvo que hemos modificado los mensajes que se muestran.

    10.4. Capa [Business]

    La capa [business, 2] proporciona la siguiente interfaz [IMetier] [IMetier.php]:

    
<?php
 
// business] layer ------------------------
interface IMétier extends IDao {
 
  // we use a person identified by his id
  public function doSomething(Personne $p): void;
}

    Comentarios

    • La interfaz [IMétier] extiende la interfaz [IDao]. Esto no es obligatorio en absoluto. Lo hacemos aquí porque el ejemplo es sencillo;
    • línea 7: el método [doSomething] es específico de la capa [Business];

    La interfaz [IMetier] será implementada por la siguiente clase [Métier] [Métier.php]:

    
<?php
 
class Métier implements IMétier {
  // layer [dao]
  private $dao;
 
  // getter / setter
  public function setDao(IDao $dao): void {
    $this->dao = $dao;
  }
 
  public function getDao(): IDao {
    return $this->dao;
  }
 
  // a person is exploited
  public function doSomething(Personne $p): void {
    // treatment
    print "Métier : Traitement métier de la personne $p\n";
  }
 
  // safeguarding the individual
  public function save(Personne $p): void {
    print "[Métier] : Sauvegarde de la personne $p\n";
    // the [dao] layer is asked to make the backup
    $this->dao->save($p);
  }
 
  public function get(int $id): Personne {
    print "[Métier] : récupération de la personne d'identifiant $id\n";
    // we ask for the person in the diaper [dao]
    $personne = $this->dao->get($id);
    return $personne;
  }
 
}

    Comentarios

    • línea 5: la capa [business] debe tener una referencia a la capa [DAO] para poder utilizar sus métodos;
    • Líneas 8-10: El método [setDao] permite que la capa [business] reciba una referencia a la capa [DAO]. Tenga en cuenta que el tipo de parámetro es [IDao]. Esto significa que la capa [business] podrá trabajar con cualquier clase que implemente la interfaz [IDao]. Si cambiamos de una capa [Dao1] a una capa [Dao2] y ambas implementan la interfaz [IDao], no es necesario reescribir la capa [business];
    • líneas 17-20: implementación de [IMetier::doSomething];
    • líneas 23-27: implementación de [IMetier::save]. Este método debe guardar una persona en un almacén de datos. La capa [business] no puede hacer esto. Recurre a la capa [DAO] para realizar este guardado;
    • líneas 29-34: implementación de [IMetier::get]. Este método debe recuperar de un almacén de datos a la persona cuyo ID se le pasa como parámetro. La capa [business] no sabe cómo hacerlo. Recurre a la capa [DAO] para que realice la tarea (línea 32);

    Conclusión

    Siempre que la capa [business] necesite acceder a datos almacenados en el almacén de datos, debe pasar por la capa [DAO], que se creó para acceder a estos datos.

    10.5. Script principal

    Escribiremos dos scripts que actuarán como coordinadores de esta aplicación. El primero [main1.php] utilizará la capa [Dao1], mientras que el segundo [main2.php] utilizará la capa [Dao2]. Queremos demostrar que esto no tiene ningún impacto en el código de la capa [Business].

    El script [main1.php] es el siguiente:

    
<?php
 
// strict adherence to function parameters
declare (strict_types=1);
 
// inclusion classes and interfaces
require_once __DIR__."/Personne.php";
require_once __DIR__."/IDao.php";
require_once __DIR__."/IMetier.php";
require_once __DIR__."/Dao1.php";
require_once __DIR__."/Métier.php";
 
// test ----------------
// layer creation
$dao1 = new Dao1();
$métier = new Métier();
$métier->setDao($dao1);
// using the [business] layer
$personne = $métier->get(4);
$métier->doSomething($personne);
$métier->save($personne);

    Comentarios

    • Repasemos algunos puntos: el script [main1.php] actúa como coordinador de la aplicación. Crea la estructura en capas de la aplicación (líneas 15–17) y, a continuación, comienza a comunicarse con la capa [business] (líneas 19–21). La estructura en capas es la siguiente:

    Según este diagrama, el script [main1.php] solo debería interactuar con la capa [business]. No debería interactuar con la capa [DAO], aunque esto sea teóricamente posible.

<?php
