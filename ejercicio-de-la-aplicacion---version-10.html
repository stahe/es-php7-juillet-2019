    20. Ejercicio de la aplicación – Versión 10

    La versión anterior mostraba que los datos fiscales, compartidos por todos los usuarios de la aplicación, debían almacenarse en una caché de ámbito [Application]. Utilizaremos un servidor Redis [https://redis.io] para implementar esto.

    20.1. Redis

    La memoria de ámbito [Application] se implementará mediante un servidor Redis. Los scripts PHP que necesiten esta memoria de aplicación serán clientes de este servidor:

    20.2. Instalación de Redis

    Laragon incluye un servidor Redis que no está habilitado de forma predeterminada. Por lo tanto, debes empezar por habilitarlo:

    • En [3], habilita el servidor [Redis];
    • En [4], deja el puerto [6379] como el predeterminado utilizado por los clientes de Redis;

    Los servicios de Laragon se reinician automáticamente tras habilitar Redis:

    20.3. El cliente Redis en modo de comandos

    El servidor Redis se puede consultar en modo de comandos. Abre un terminal de Laragon (consulta la sección de enlaces):

    • En [1], el comando [redis-cli] inicia el cliente en modo de comandos para el servidor Redis;

    A fecha de julio de 2019, el cliente de Redis admite 172 comandos para interactuar con el servidor [https://redis.io/commands#list]. Uno de ellos [recuento de comandos] [2] muestra este número [3].

    Solo trataremos las que necesitamos para nuestra aplicación PHP. Utilizaremos Redis con un único propósito: almacenar una matriz [‘atributo’=>’valor’] en la memoria de Redis. Esto se hace con el comando de Redis [set atributo valor] [4]. A continuación, el valor se puede recuperar utilizando el comando [get atributo] [5]. Eso es todo lo que necesitaremos.

    Puede que sea necesario borrar la memoria de Redis. Esto se hace con el comando [flushdb] [6]. A continuación, si consultamos el valor del atributo [title] [7], obtenemos una referencia [nil] [8] que indica que no se ha encontrado el atributo. También podemos utilizar el comando [exists] [9-10] para comprobar si existe un atributo.

    Para salir del cliente de Redis, escribe el comando [quit] [11].

function doInternalServerError(string $message, Response $response, array $infos,
  Logger $logger = NULL, \Predis\Client $predisClient = NULL) {
  // $message: error message
  // $response : answer HTTP
  // $infos: information table for sending mail
  // $result: results table
  // $logger: application logger
  // $predisClient: a customer [predis]
  //
  // send an e-mail to the administrator
  // SendAdminMail intercepts all exceptions and logs them itself
  $infos['message'] = $message;
  $sendAdminMail = new SendAdminMail($infos, $logger);
  $sendAdminMail->send();
  // an error code 500 is sent to the customer
  sendResponse($response, ["erreur" => $message], Response::HTTP_INTERNAL_SERVER_ERROR, [], $logger, $predisClient);
}

// function to send HTTP response to client
function sendResponse(Response $response, array $result, int $statusCode,
  array $headers, Logger $logger = NULL, \Predis\Client $predisClient = NULL) {
  // $response : answer HTTP
  // $result: results table
  // $statusCode: HTTP response status
  // $headers: HTTP headers to be included in the response
  // $logger: application logger
  // $predisClient: a customer [predis]
  //
  // status HTTTP
  $response->setStatusCode($statusCode);
  // body
  $body = \json_encode(["réponse" => $result], JSON_UNESCAPED_UNICODE);
  $response->setContent($body);
  // headers
  $response->headers->add($headers);
  // shipping
  $response->send();
  // log
  if ($logger != NULL) {
    $logger->write("$body\n");
    $logger->close();
  }
  // close connection [redis]
  if ($predisClient != NULL) {
    $predisClient->disconnect();
  }
}

    Comentarios

    • línea 15: asignamos el alias [ServerDaoWithRedis] a la clase [\Application\ServerDaoWithSession] para reflejar el cambio en la implementación del script del servidor;
    • líneas 18-19: se mantiene la sesión. Aquí debemos tener en cuenta dos datos:
      • el hecho de que el usuario se ha autenticado correctamente. Esta información tiene alcance [session]: está vinculada a un usuario específico y no es válida para otros usuarios;
      • los datos de la administración tributaria. Esta información tiene un ámbito [application]: no está vinculada a un usuario específico, sino que se aplica a todos los usuarios;
    • líneas 54-64: creación del cliente [redis] que se comunicará con el servidor [redis]. Este cliente se comunicará con el puerto predeterminado del servidor. Si el servidor no se comunicara en su puerto predeterminado o si no estuviera en la máquina [localhost], sería necesario pasar esta información al constructor de la clase [\Predis\Client];
    • línea 59: el cliente se conecta inmediatamente al servidor para comprobar si responde;
    • líneas 60–65: si falla la conexión con el servidor Redis, se envía una respuesta de error al cliente y se envía un correo electrónico al administrador de la aplicación;
    • línea 67: consultamos el servidor [redis] en busca de la clave [taxAdminData]. Si no se encuentra, los datos fiscales se recuperan de la base de datos (línea 72);
    • línea 75: la clave [taxAdminData] se almacena en la memoria [redis] junto con la cadena JSON de la variable [$taxAdminData], que es un objeto de tipo [TaxAdminData]. El método [$redis→set] espera una cadena como valor de la clave. Por lo tanto, intentará convertir el objeto [TaxAdminData] a un tipo [string]. Esto invoca implícitamente el método [TaxAdminData->__toString], que genera la cadena JSON del objeto [TaxAdminData];
    • línea 84: la clave [taxAdminData] se encuentra en la memoria [redis], por lo que recuperamos su valor. Sabemos que se trata de la cadena JSON de un objeto [TaxAdminData]. A continuación, la analizamos para obtener una matriz de atributos;
    • línea 85: a partir de esta matriz, se instancia un nuevo objeto [TaxAdminData];
    • línea 87: se instancia la capa [dao];
