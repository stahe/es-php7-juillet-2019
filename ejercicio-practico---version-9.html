    19. Ejercicio práctico – Versión 9

    En esta versión, mejoraremos el servidor de la siguiente manera:

    • Actualmente, con cada solicitud, los datos de la administración tributaria se recuperan de la base de datos. Utilizaremos una sesión:
      • Durante la primera solicitud de un usuario, los datos de la autoridad fiscal se recuperan de la base de datos y se almacenan en la sesión;
      • Para las solicitudes posteriores del mismo usuario, los datos de la autoridad fiscal se recuperan de la sesión. Podemos esperar una ligera mejora en el tiempo de ejecución, ya que las consultas a la base de datos consumen muchos recursos;
    • el servidor registrará los eventos importantes en un archivo de texto:
      • autenticación correcta o fallida;
      • si los parámetros enviados por el cliente son válidos;
      • el resultado del cálculo de impuestos;
      • diversos casos de error;
    • en caso de error grave, se enviará un correo electrónico al administrador de la aplicación;

    También hay que modificar el cliente para que gestione la cookie de sesión que se le enviará.

    19.1. El servidor

    Nos centramos en el lado del servidor de la aplicación.

    Esta arquitectura se implementará mediante los siguientes scripts:

    19.1.1. Utilidades

    19.1.1.1. La clase [Logger]

    La clase [Logger] se utilizará para escribir registros en un archivo de texto:

    
<?php
 
namespace Application;
 
class Logger {
  // attribute
  private $resource;
 
  // manufacturer
  public function __construct(string $logsFilename) {
    // open file
    $this->resource = fopen($logsFilename, "a");
    if (!$this->resource) {
      throw new ExceptionImpots("Echec lors de la création du fichier de logs [$logsFilename]");
    }
  }

  // writing a message to the logs
  public function write(string $message) {
    fputs($this->resource, (new \DateTime())->format("d/m/y H:i:s:v") . " : $message");
  }
 
  // close log file
  public function close() {
    fclose($this->resource);
  }
 
}

    Comentarios

    • línea 7: el recurso del archivo de registro;
    • línea 10: el constructor de la clase recibe el nombre del archivo de registro como parámetro;
    • línea 12: el archivo de texto se abre en modo de adición (a+): el archivo se abrirá y se conservará su contenido. Los nuevos datos se escribirán después del contenido actual;
    • líneas 13–15: si no se ha podido abrir el archivo, se lanza una excepción;
    • líneas 19-21: el método [write] escribe el mensaje [$message] en el archivo de registro, precedido de la fecha y la hora;
    • líneas 24–16: el método [close] cierra el archivo de registro;

    Nota: La aplicación del servidor puede atender a varios clientes simultáneamente. Sin embargo, solo hay un archivo de registro para todos ellos. Por lo tanto, existe el riesgo de acceso concurrente al escribir en el archivo. Por lo tanto, las escrituras deben sincronizarse para evitar que se mezclen. PHP proporciona semáforos [https://www.php.net/manual/fr/book.sem.php] para este propósito. Ignoraremos la sincronización de escritura aquí, pero debemos ser conscientes del problema.

    19.1.1.2. La clase [SendAdminMail]

    La clase [SendAdminMail] permite enviar un correo electrónico al administrador de la aplicación en caso de que se produzca un fallo:

    
<?php
 
namespace Application;
 
class SendAdminMail {
  // attributes
  private $config;
  private $logger;
 
  // manufacturer
  public function __construct(array $config, Logger $logger = NULL) {
    $this->config = $config;
    $this->logger = $logger;
  }
 
  public function send() {
    // sends $this->config['message'] to smtp server $this->config['smtp-server'] on port $infos[smt-port]
    // if $this->config['tls'] is true, TLS support will be used
    // mail is sent from $this->config['from']
    // for recipient $this->config['to']
    // message has subject $this->config['subject']
    // attachments from $this->config['attachments'] are attached to the mail
    // the result of the method
    try {
      // message creation
      $message = (new \Swift_Message())
        // message subject
        ->setSubject($this->config["subject"])
        // sender
        ->setFrom($this->config["from"])
        // recipients with a dictionary (setTo/setCc/setBcc)
        ->setTo($this->config["to"])
        // message text
        ->setBody($this->config["message"])
      ;
      // attachments
      foreach ($this->config["attachments"] as $attachment) {
        // path of attachment
        $fileName = __DIR__ . $attachment;
        // check that the file exists
        if (file_exists($fileName)) {
          // attach the document to the message
          $message->attach(\Swift_Attachment::fromPath($fileName));
        } else {
          if ($this->logger !== NULL) {
            // error
            $this->logger->write("L'attachement [$fileName] n'existe pas\n");
          }
        }
      }
      // protocol TLS ?
      if ($this->config["tls"] === "TRUE") {
        // TLS
        $transport = (new \Swift_SmtpTransport($this->config["smtp-server"], $this->config["smtp-port"], 'tls'))
          ->setUsername($this->config["user"])
          ->setPassword($this->config["password"]);
      } else {
        // no TLS
        $transport = (new \Swift_SmtpTransport($this->config["smtp-server"], $this->config["smtp-port"]));
      }
      // the shipment manager
      $mailer = new \Swift_Mailer($transport);
      // sending the message
      $mailer->send($message);
      // end
      if ($this->logger !== NULL) {
        $this->logger->write("Message [{$this->config["message"]}] envoyé à {$this->config["to"]}\n");
      }
    } catch (\Throwable $ex) {
      // error
      if ($this->logger !== NULL) {
        $this->logger->write("Erreur lors de l'envoi du message [{$this->config["message"]}] à {$this->config["to"]}\n");
      }
    }
  }
 
}

Por lo tanto, no se realizará ninguna consulta a la base de datos.

function doInternalServerError(string $message, Response $response, Logger $logger = NULL, array $infos) {

// function to send HTTP response to client
function sendResponse(Response $response, array $result, int $statusCode, array $headers, Logger $logger) {
  // $response : answer HTTP
  // $result: results table
  // $statusCode: HTTP response status
  // $headers: HTTP headers to be included in the response
  // $logger: application logger
  //
  // status HTTTP
  $response->setStatusCode($statusCode);
  // body

  $response->setContent($body);
  // headers
  $response->headers->add($headers);
  // shipping
  $response->send();
  // log
  if ($logger != NULL) {
    $logger->write("$body\n");
    $logger->close();
  }

<?php
 
namespace Application;
 
// dependencies
use \Symfony\Component\HttpClient\HttpClient;
 
class ClientDao implements InterfaceClientDao {

  // attributes

  // tAX CALCULATION
  public function calculerImpot(string $marié, int $enfants, int $salaire): array {
    // session cookie ?
    if (!$this->sessionCookie) {
      // create a HTTP customer
      $httpClient = HttpClient::create([
          'auth_basic' => [$this->user["login"], $this->user["passwd"]],
          "verify_peer" => false
      ]);
      // make the request to the server without a session cookie
      $response = $httpClient->request('GET', $this->urlServer,

            "marié" => $marié,
            "enfants" => $enfants,
            "salaire" => $salaire
          ]
      ]);
    } else {
      // make a request to the server with the session cookie
      // create a HTTP customer
      $httpClient = HttpClient::create([
          "verify_peer" => false
      ]);
      $response = $httpClient->request('GET', $this->urlServer,
        ["query" => [
            "marié" => $marié,
            "enfants" => $enfants,
            "salaire" => $salaire
          ],
          "headers" => ["Cookie" => $this->sessionCookie]

    $array = \json_decode($json, true);

    print "$json=json\n";
    // retrieve response status
    $statusCode = $response->getStatusCode();
    // mistake?
    if ($statusCode !== 200) {
      // we have an error - we throw an exception

      $message = \json_encode($réponse, JSON_UNESCAPED_UNICODE);
      throw new ExceptionImpots($message);

    if (!$this->sessionCookie) {

          }

    // we return the answer

    • líneas 40-53: para las solicitudes posteriores, normalmente disponemos de la cookie de sesión. Por lo tanto, no enviamos la información de autenticación (líneas 42-44);
    • líneas 69-82: la respuesta del servidor a la primera solicitud incluirá una cookie de sesión. La recuperamos. Este código ya se ha utilizado y explicado en la sección enlazada;
    • línea 78: la cookie de sesión recuperada se almacena en el atributo de clase [$sessionCookie];

    Nota: Podríamos haber conservado la versión antigua de la capa [dao] y haber realizado la autenticación en cada solicitud, ya que el coste es insignificante. Con fines didácticos, queríamos demostrar cómo un cliente HTTP puede gestionar una sesión.

    En una clase de prueba de [Codeception], el constructor se ejecuta en cada prueba.

    • Línea 21: Por lo tanto, se crea un nuevo [ClientDao] para cada prueba con una cookie de sesión NULL. Esto explica por qué este cliente no se beneficia de ninguna sesión;

    Este ejemplo nos muestra que la sesión no es el lugar adecuado para almacenar datos de la administración tributaria. De hecho, estos datos se comparten entre todos los usuarios de la aplicación. Sin embargo, aquí se duplican en cada una de sus sesiones.

    En la programación web, existen tres tipos de visibilidad para los datos compartidos:

    • datos compartidos por todos los usuarios de la aplicación web. Por lo general, se trata de datos de solo lectura. PHP no admite de forma nativa este tipo de almacenamiento;
    • datos compartidos entre solicitudes del mismo cliente. Estos datos se almacenan en la sesión. Nos referimos a esto como la sesión del cliente para denotar el almacenamiento del cliente. Todas las solicitudes de un cliente tienen acceso a esta sesión. Pueden almacenar y leer información allí. En los scripts anteriores, esta sesión está implementada por el objeto de Symfony [HttpFoundation\Session\Session];
    • la memoria de la solicitud, o contexto de la solicitud. La solicitud de un usuario puede procesarse mediante varias acciones sucesivas. El contexto de la solicitud permite que la Acción 1 pase información a la Acción 2. En los scripts anteriores, la solicitud se implementa mediante el objeto de Symfony [HttpFoundation\Request] y su memoria mediante el atributo [HttpFoundation\Request::attributes];

    Existen bibliotecas de terceros que proporcionan a PHP el estado de la aplicación. La nueva versión del ejercicio de la aplicación muestra el uso de una de ellas.
