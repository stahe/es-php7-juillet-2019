    12. Uso del SGBD MySQL

    Ahora escribiremos scripts PHP utilizando una base de datos MySQL:

    En la arquitectura anterior, el script PHP (1) no se comunica directamente con el SGBD (Sistema de Gestión de Bases de Datos) (3). Se comunica con un intermediario denominado controlador de SGBD. PHP proporciona una interfaz estándar para estos controladores, la interfaz PDO (PHP Data Objects). Esta interfaz está implementada por diferentes clases adaptadas a cada SGBD: una clase para el SGBD MySQL, otra para el SGBD PostgreSQL… Para cambiar de SGBD, cambiamos de controlador:

    El controlador PDO aísla el script PHP (1) del SGBD (3, 6). Dado que estos controladores implementan una interfaz estándar, cabría esperar que el script PHP (1) permaneciera inalterado al cambiar del SGBD MySQL (3) al SGBD PostgreSQL (6). En realidad, este ideal no existe. De hecho, para comunicarse con el SGBD, el script PHP envía comandos SQL (lenguaje de consulta estructurado). Se trata de un lenguaje implementado por todos los SGBD, pero es incompleto. En consecuencia, los SGBD le han añadido comandos propios. Esta es una de las principales causas de incompatibilidad entre los SGBD. Además, los tipos de datos que se pueden utilizar en las bases de datos pueden diferir de un SGBD a otro. Por ejemplo, PostgreSQL admite una gama mucho más amplia de tipos de datos que el SGBD MySQL. Esta es una segunda causa de incompatibilidad. Otra causa es el manejo de las claves primarias automáticas (generadas por el SGBD): prácticamente todos los SGBD tienen su propia política. Etc… Existen numerosas causas de incompatibilidad.

    Si desea evitar reescribir el script PHP (1) al cambiar de MySQL (3) a PostgreSQL (6), por lo general necesitará insertar una nueva capa entre el script PHP (1) y el controlador PDO (2, 5), cuya función será resolver las incompatibilidades entre los dos SGBD. Sin embargo, en los casos sencillos con los que nos encontraremos, esta capa adicional no será necesaria.

    Ahora utilizaremos el SGBD MySQL. Este está incluido en el paquete Laragon (véase la sección de enlaces).

    Si el lector es nuevo en los conceptos de bases de datos y SQL, puede que le resulte útil el documento [http://sergetahe.com/cours-tutoriels-de-programmation/cours-tutoriel-sql-avec-le-sgbd-firebird/]. Este documento utiliza el SGBD Firebird en lugar de MySQL, pero cubre los fundamentos de las bases de datos y SQL. Al igual que MySQL, Firebird ofrece una versión de libre acceso que ocupa poco espacio en memoria.

    12.2. Conexión a una base de datos MySQL

    La conexión a un SGBD se realiza creando un objeto PDO. El constructor acepta varios parámetros:

    $dbh=new PDO(string $dsn,string $user,string $passwd,array $driver_options)

    Los parámetros tienen los siguientes significados:

    $dsn
    (Nombre de la fuente de datos) es una cadena que especifica el tipo de SGBD y su ubicación en Internet. La cadena «mysql:host=localhost» indica que se trata de un DBMS MySQL que se ejecuta en el servidor local. Esta cadena puede incluir otros parámetros, como el puerto de escucha del DBMS y el nombre de la base de datos a la que queremos conectarnos: «mysql:host=localhost:port=3306:dbname=dbpersonnes»;
    $user
    nombre de usuario de la persona que inicia sesión;
    $passwd
    su contraseña;
    $driver_options
    una matriz de opciones para el controlador del SGBD;

    Solo es obligatorio el primer parámetro. El objeto creado de esta manera servirá entonces como base para todas las operaciones realizadas en la base de datos a la que se haya conectado. Si no se ha podido crear el objeto PDO, se lanza una excepción PDOException.

    A continuación se muestra un ejemplo de conexión [mysql-01.php]:

    
<?php
 
// connection to a local MySql database
// user identity is (admpersonnes,nobody)
const ID = "admpersonnes";
const PWD = "nobody";
const HOTE = "localhost";
 
try {
  // connection
  $dbh = new PDO("mysql:host=".HOTE, ID, PWD);
  print "Connexion réussie\n";
  // closing the connection
  $dbh = NULL;
} catch (PDOException $e) {
  print "Erreur : " . $e->getMessage() . "\n";
  exit();
}

    12.3. Creación de una tabla

    El script [mysql-02.php] muestra cómo crear una tabla en una base de datos:

    
<?php
 
// database identity
const DSN = "mysql:host=localhost;dbname=dbpersonnes";
// user login
const ID = "admpersonnes";
const PWD = "nobody";
 
try {
  // connection to the MySql database
  $connexion = new PDO(DSN, ID, PWD);
  // delete the people table if it exists
  $sql = "drop table personnes";
  $connexion->exec($sql);
  // create people table
  $sql = "create table personnes (prenom varchar(30) NOT NULL, nom varchar(30) NOT NULL, age integer NOT NULL, primary key(nom,prenom))";
  $connexion->exec($sql);
} catch (PDOException $ex) {
  // error display
  print "Erreur : " . $ex->getMessage() . "\n";
} finally {
  // disconnect if necessary
  $connexion = NULL;
}
// end
print "Terminé\n";
exit;

    Comentarios

    • línea 11: conecta a la base de datos. Esto es siempre lo primero que hay que hacer. El resultado de la conexión es un objeto [PDO] a través del cual se realizarán las operaciones de la base de datos;
    • línea 13: la instrucción SQL [drop table people] eliminará la tabla [people] de la base de datos [people_db]. Si la tabla [people] no existe, esto no provoca un error;
    • línea 14: ejecución de la instrucción SQL anterior en la base de datos [dbpersonnes]. Esta ejecución puede lanzar una [PDOException], que se interceptará en la línea 18;
    • Línea 16: Esta instrucción SQL crea una tabla llamada [people]. Una tabla se compone de filas y columnas. Las columnas conforman lo que se denomina la estructura de la tabla. Las filas conforman el contenido de la tabla. Una base de datos puede contener una o más tablas. La tabla [people] tendrá tres columnas:
      • first_name: el nombre de pila de una persona como una cadena de hasta 30 caracteres;
      • last_name: el apellido de esa misma persona como una cadena de hasta 30 caracteres;
      • age: la edad de la persona como un número entero;
      • El atributo NOT NULL en una columna exige que la columna tenga un valor. Si no se proporciona uno, se produce una [PDOException];
      • [primary key(last_name,first_name)] establece una clave principal para la tabla [people]. Una clave primaria tiene un valor único para cada fila de la tabla. Aquí, la clave primaria se obtiene concatenando las columnas [last_name] y [first_name] de la fila. Esta restricción garantiza que la tabla no pueda contener dos personas con el mismo apellido y nombre, es decir, dos personas con el mismo nombre. Crear una entrada duplicada para una persona en la tabla provoca una [PDOException];
    • línea 17: ejecución de la consulta SQL en la base de datos [dbpersonnes];
    • línea 20: si se produce una [PDOException], se muestra el mensaje de error asociado;
    • líneas 21-24: introducimos la cláusula [finally] en todos los casos, se produzca o no una excepción, para cerrar la conexión a la base de datos (línea 23);

    Resultados:

    Si el script se ejecuta sin errores, la tabla se puede ver en phpMyAdmin:

    • en [3] la base de datos;
    • en [4], se muestra la tabla;
    • en [5], la estructura de la tabla se muestra en la pestaña [Estructura];
    • en [6-8], las tres columnas de la tabla;
    • en [9], ninguna de las tres columnas puede estar vacía;

    • en [10], la lista de índices de la tabla. Un índice permite encontrar filas en la tabla con un índice específico más rápido que si se escanearan secuencialmente las filas de la tabla. La clave principal siempre forma parte de los índices, pero un índice puede no ser una clave principal;
    • en [11], el índice es la clave principal en este caso;
    • en [12], el índice está formado por las columnas [apellido, nombre] de cada fila;

    • línea 3: creación de la tabla [people] con tres columnas (nombre, apellido, edad) y la clave principal (apellido, nombre);
    • líneas 4–10: inserción de 7 filas en la tabla [people];
    • línea 6: esta instrucción de inserción debería fallar porque intenta la misma inserción que la línea 5. La restricción de la clave principal debería impedir esta inserción: dos personas no pueden tener el mismo nombre y apellido;

    El script PHP encargado de ejecutar las sentencias SQL de este archivo de texto es el siguiente [mysql-03.php]:

    
<?php
 
// database identity
const DSN = "mysql:host=localhost;dbname=dbpersonnes";
// user login
const ID = "admpersonnes";
const PWD = "nobody";
// identity of the SQL command text file to be executed
const SQL_COMMANDS_FILENAME = "creation.txt";
 
// open database connection MySql
try {
  $connexion = new PDO(DSN, ID, PWD);
} catch (PDOException $ex) {
  // error display
  print "Erreur : " . $ex->getMessage() . "\n";
  exit;
}
// we want every SGBD error to trigger an exception
$connexion->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
// order file execution SQL
$erreurs = exécuterCommandes($connexion, SQL_COMMANDS_FILENAME, TRUE, FALSE);
// locking connection
$connexion = NULL;
//display number of errors
printf("\n-----------------------\nIl y a eu %d erreur(s)\n", count($erreurs));
for ($i = 0; $i < count($erreurs); $i++) {
  print "$erreurs[$i]\n";
}
 
// it's over
print "Terminé\n";
exit;
 
// ---------------------------------------------------------------------------------
function exécuterCommandes(PDO $connexion, string $SQLFileName, bool $suivi = FALSE, bool $arrêt = TRUE): array {
// uses the $connexion connection
// executes the SQL commands contained in the SQLFileName text file
// this is a file of SQL commands to be executed one per line
// if $suivi=1 then each execution of a SQL order is displayed as a success or failure
// if $arrêt=1, the function stops on the 1st error encountered, otherwise it executes all sql commands
// the function returns an array (nb of errors, error1, error2...)
// check for the presence of the SQLFileName file
 
  if (!file_exists($SQLFileName)) {
    return ["Le fichier [$SQLFileName] n'existe pas"];
  }
 
  // execution of SQL queries contained in SQLFileName
  // we put them in a table
  $requêtes = file($SQLFileName);
  // mistake?
  if ($requêtes === FALSE) {
    return ["Erreur lors de l'exploitation du fichier SQL [$SQLFileName]"];
  }
  // execute requests one by one - initially no errors
  $erreurs = [];
  $i = 0;
  $fini = FALSE;
  while ($i < count($requêtes) && !$fini) {
    // retrieve the query text
    // trim will remove the end-of-line marker
    $requête = trim($requêtes[$i]);
    // empty query?
    if (strlen($requête) == 0) {
      // ignore the request and move on to the next request
      $i++;
      continue;
    }
    try {
      // query execution - an exception may be thrown
      $connexion->exec($requête);
      // screen tracking or not?
      if ($suivi) {
        print "$requête : Exécution réussie\n";
      }
    } catch (PDOException $ex) {
      // an error has occurred
      addError($erreurs, $requête, $ex->getMessage(), $suivi);
      // shall we stop?
      $fini = $arrêt;
    }
    // following request
    $i++;
  }
  // result
  return $erreurs;
}
 
function addError(array &$erreurs, string $requête, string $msg, bool $suivi): void {
  // add an error msg
  $msg = "$requête : Erreur (" . $msg . ")";
  $erreurs[] = $msg;
  // screen tracking or not?
  if ($suivi) {
    print "$msg\n";
  }
}

    Comentarios

    • La función [executeCommands] (líneas 36–89) se encarga de ejecutar los comandos SQL que se encuentran en el archivo de texto [$SQLFileName] (parámetro 2). Para ejecutarlos, utiliza la conexión abierta [$connection] (parámetro 1) al servidor MySQL. El tercer parámetro [$log] es un valor booleano que controla la salida en pantalla: si es TRUE, la instrucción SQL ejecutada se muestra en pantalla junto con su éxito o fallo; de lo contrario, la ejecución de la instrucción SQL es silenciosa. El cuarto parámetro [$stop] controla qué hacer cuando falla un comando SQL: si es TRUE, indica que la ejecución de los comandos SQL debe detenerse; de lo contrario, continúa. La función [executeCommands] devuelve una matriz de mensajes de error, vacía si no se han producido errores;
    • líneas 11–18: abrimos la conexión a la base de datos MySQL [dbpersonnes]. Si falla la apertura de la conexión, se muestra un mensaje de error y el proceso se detiene (líneas 14–18);
    • línea 22: A continuación, pasamos una conexión abierta a la función [executeCommands]. Se cerrará cuando la función devuelva un resultado (línea 24);
    • Línea 20: Antes de pasarla a la función [executeCommands], se configura la conexión. En caso de error, las operaciones SQL con un objeto [PDO] pueden devolver el valor booleano FALSE (valor por defecto) o lanzar una excepción. La línea 20 opta por esta última opción. De hecho, es fácil «olvidarse» de comprobar el resultado booleano de la ejecución de un comando SQL. Esto acabará provocando un error en otra parte del código, lo que dificultará rastrear su origen. En caso de una excepción no gestionada (sin bloque catch), la excepción se propagará hacia arriba por la cadena de código hasta que encuentre un bloque catch o llegue al intérprete de PHP, que interceptará la excepción. En este caso, se muestran la naturaleza de la excepción y su origen en el código;
    • línea 22: se llama a la función [executeCommands] para ejecutar el archivo de comando SQL [$SQLFileName];
    • líneas 45-47: verificamos que el archivo de comandos SQL existe realmente. Si no es así, registramos el error y devolvemos este resultado;
    • línea 51: los comandos SQL se colocan en una matriz [$queries]. Líneas 53–55: si la operación falla, se devuelve una matriz de errores que contiene un único mensaje;
    • línea 57: acumulamos los errores en la matriz [$errors];
    • línea 58: número de consulta;
    • línea 59: el booleano [$finished] controla la ejecución de las sentencias SQL de la matriz [$queries]. Cuando se convierte en TRUE, la ejecución se detiene;
    • línea 60: recorremos todas las consultas;
    • línea 63: extraemos el texto del comando SQL #i. La función [trim] elimina los espacios antes y después del texto del comando SQL. Por «espacios» nos referimos al carácter de espacio \b, al retorno de carro \r, al salto de línea \n, al salto de página \f, a la tabulación \t… Lo importante aquí es que se eliminará el salto de línea del texto SQL;
    • líneas 65–69: si el texto SQL está vacío, se ignora la consulta y pasamos a la siguiente;
    • línea 72: enviamos el comando SQL al servidor MySQL. El método [PDO::exec] lanzará una excepción si la ejecución falla. Tenga en cuenta que este comportamiento se debe a la configuración establecida en la línea 20;
    • línea 79: el mensaje de error se añade a la matriz de errores;
    • línea 81: se establece el valor booleano [$fini] que controla el bucle. Si el parámetro [$arrêt] (línea 36) es TRUE, el bucle debe detenerse;

    Comentarios

    Aquí nos centramos en las líneas 16 a 24, que añaden dos personas a la tabla «people» de la base de datos [dbpersonnes].

    • Línea 21: «Preparamos» una instrucción SQL parametrizada. Los parámetros van precedidos por el carácter : :last_name, :first_name, :age. Para «preparar» una instrucción SQL, utilizamos el método [PDO::prepare]. El resultado es un tipo [PDOStatement]. La «preparación» no es ejecución: no se ejecuta nada;
    • Línea 23: Ejecución de la instrucción «preparada» mediante el método [PDOStatement::execute]. Para ello, hay que asignar valores a los parámetros :last_name, :first_name y :age. Hay varias formas de hacerlo. Aquí utilizamos un diccionario cuyas claves son los parámetros de la instrucción preparada, que pasamos al método [PDOStatement::execute]. Otra forma de hacerlo es asignar un valor a los parámetros utilizando el método [PDOStatement::bindValue($parameter,$value)]. Por ejemplo: 
    
$statement→bindValue(“nom”,”Langevin”);
$statement→bindValue(“prenom”,”Paul”);
$statement→bindValue(“age”,47);
$statement→execute();

    El inconveniente es que hay que repetir esta instrucción para cada parámetro. Por lo tanto, el método del diccionario puede resultar más práctico. El método [PDOStatement::execute] devuelve FALSE si la ejecución falla;

    • el método utilizado aquí para realizar las inserciones:
      • una instrucción preparada;
      • n ejecuciones de la instrucción preparada;

    es más eficiente en términos de tiempo de ejecución que ejecutar n sentencias SQL diferentes. Por lo tanto, este método es preferible. Se puede utilizar para sentencias SQL SELECT, UPDATE, DELETE e INSERT. En el caso de una sentencia SQL SELECT, tras ejecutarla con [PDOStatement::execute], las filas de resultados se recuperan utilizando el método [PDOStatement::fetchAll];

    12.7. Uso de transacciones

    Una transacción permite agrupar una secuencia de sentencias SQL en una única unidad de ejecución: o bien todas las sentencias se ejecutan correctamente, o bien una de ellas falla, en cuyo caso se revierten todas las sentencias SQL anteriores a ella. En otras palabras, cuando se utiliza una transacción para ejecutar sentencias SQL, una vez completada la transacción, la base de datos se encuentra en un estado estable:

    • o bien en un nuevo estado creado por la ejecución correcta de todas las sentencias SQL de la transacción;
    • o en el estado en el que se encontraba antes de que comenzara a ejecutarse la transacción;

    Volveremos al ejemplo de la ejecución de las sentencias SQL contenidas en un archivo de texto que se ha comentado en la sección anterior. Incluiremos esta ejecución dentro de una transacción. Las sentencias SQL estarán contenidas en el siguiente archivo [sql2.txt]:

    
set names 'utf8'
select * from personnes
select nom,prenom from personnes order by nom asc, prenom desc
select * from personnes where age between 20 and 40 order by age desc, nom asc, prenom asc
insert into personnes values('Josette','Bruneau',46)
update personnes set age=47 where nom='Bruneau'
select * from personnes where nom='Bruneau'
delete from personnes where nom='Bruneau'
select * from personnes where nom='Bruneau'
insert into personnes values('Josette','Bruneau',46)
select * from personnes where nom='Bruneau'
xselect * from personnes where nom='Bruneau'

    El orden incorrecto de la línea 12 provocará que toda la transacción falle. Por lo tanto, la base de datos debería volver al estado en el que se encontraba antes de la transacción. function exécuterCommandes(PDO $connexion, string $SQLFileName, bool $suivi = FALSE): array {
// uses the $connexion connection
// executes the SQL commands contained in the SQLFileName text file
// this is a file of SQL commands to be executed one per line
// SQL commands are executed in a transaction
// if one of the orders fails, the transaction is cancelled and the database is restored to its pre-transaction state
// if $suivi=1 then each execution of a SQL order is displayed as a success or failure
// the function returns an array (nb of errors, error1, error2...)
//
// check for the presence of the SQLFileName file
  if (!file_exists($SQLFileName)) {
    return ["Le fichier [$SQLFileName] n'existe pas"];
  }
  // execution of SQL queries contained in SQLFileName
  // we put them in a table
  $requêtes = file($SQLFileName);
  // mistake?
  if ($requêtes === FALSE) {
    return ["Erreur lors de l'exploitation du fichier SQL [$SQLFileName]"];
  }
  // requests will be placed in a transaction
  $connexion->beginTransaction();
  // execute requests one by one - initially no errors
  $erreurs = [];
  $i = 0;
  $fini = FALSE;
  while ($i < count($requêtes) && !$fini) {
    // retrieve the query text
    // trim will remove the end-of-line marker
    $requête = trim($requêtes[$i]);
    // empty query?
    if (strlen($requête) == 0) {
      // ignore the request and move on to the next request
      $i++;
      continue;
    }
    // query execution
    // we retrieve its name
    $commande = "";
    if (preg_match("/^\s*(\S+)/", $requête, $champs)) {
      $commande = strtolower($champs[0]);
    }
    try {
      // is this a SELECT order?
      if ($commande === "select") {
        $résultat = $connexion->query($requête);
      } else {
        $résultat = $connexion->exec($requête);
      }
      // screen tracking or not?
      if ($suivi) {
        print "[$requête] : Exécution réussie\n";
      }
      // the result of execution is displayed
      afficherInfos($commande, $résultat);
    } catch (PDOException $ex) {
      // an error has occurred
      addError($erreurs, $requête, $ex->getMessage(), $suivi);
      // we stop at the next turn
      $fini = TRUE;
    }
    // following request
    $i++;
  }
  // end of transaction
  if (!$fini) {
    // no errors: transaction validated
    $connexion->commit();
  } else {
    // there have been errors: the transaction is cancelled
    $connexion->rollBack();
    // add error
    addError($erreurs, "", "Transaction annulée", $suivi);
  }
  // result
  return $erreurs;
}

    Comentarios

    Hemos resaltado los cambios respecto al script original [mysql-04.php].

    • líneas 22 y 36: la función [executeCommands] ha perdido su cuarto parámetro [$stop=TRUE]. Esto se debe a que, dado que los comandos SQL se ejecutan dentro de una transacción, cualquier error provocará que la transacción se revierta;
    • líneas 40–41: llamada a la función de transacción;
    • línea 57: se inicia una transacción. A partir de este momento, cualquier comando SQL ejecutado dentro del bucle de las líneas 62–99 se ejecuta dentro de esta transacción;
    • líneas 101–109: el valor booleano [$fini] es TRUE si se ha producido un error (línea 95). Cuando es FALSE, no se ha producido ningún error y la transacción se confirma (línea 103). Cuando es TRUE, se han producido errores, por lo que la transacción se revierte (línea 106) y el error de transacción se añade a la lista de errores (línea 108);

    Resumen

    • Una transacción se inicia con el método [PDO::beginTransaction];
    • Se confirma tras el éxito mediante el método [PDO::commit];
    • Se cancela en caso de fallo mediante el método [PDO::rollback];

    Cuando se trabaja con una base de datos, es recomendable incluir todas las operaciones SQL dentro de una transacción para aislarlas de otros usuarios de la base de datos (este es también su propósito). Una transacción debe ser lo más breve posible. Por lo tanto, no olvides finalizarla con un [commit] o un [rollback], según corresponda.
