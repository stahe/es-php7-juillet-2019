    7. Excepciones y errores

    Cuando un método de clase encuentra un error irrecuperable (el archivo no existe, la base de datos no está conectada, la conexión de red se ha interrumpido), no muestra un error en la consola (archivo, base de datos), sino que lanza una excepción. Todas las excepciones heredan de la clase [\Exception]. Además de las excepciones, las operaciones internas de PHP también generan errores cuya clase base es la clase [\Error]. Ambas clases implementan la interfaz PHP [\Throwable].

    7.4. Errores predefinidos en PHP 7

    PHP 7 define varias clases de error:

    La clase [\Error] es la clase padre de todos los errores predefinidos en PHP. La clase [ErrorException] permite encapsular una instancia de la clase [\Error] dentro de una instancia de la clase [\Exception]. Esto permite un manejo estandarizado de los errores al tratar únicamente con excepciones.

    7.5. Ejemplo 1

    El primer ejemplo [exceptions-01.php] muestra tanto errores de PHP como una excepción:

    
<?php
 
// display all errors
ini_set("error_reporting", E_ALL);
ini_set("display_errors", "on");
// code --------
$var=[];
// unknown key
print $var["abcd"];
// division by zero
$var=7/0;
var_dump($var);
// fixed terminal board
$array = new \SplFixedArray(5);
$array[1] = 2;
$array[4] = "foo";
// index outside the limits
$array[5]=8;

    Comentarios

    • Línea 4: Le indicamos a PHP que informe de todos los errores. El segundo parámetro es el nivel de error solicitado:

    • línea 5: pedimos que se muestren los errores en la consola;
    • línea 9: accedemos a un elemento inexistente de la matriz [$var];
    • línea 11: realizamos una división por cero;
    • línea 14: creamos una instancia de la clase [SplFixedArray]. Esta clase nos permite crear una matriz con límites fijos e índices enteros;
    • línea 18: accedemos a un elemento inexistente de la matriz;

    7.6. Gestión de excepciones

    El script [exceptions-02.php] muestra cómo gestionar excepciones:

    
<?php
 
// all errors are displayed
ini_set("error_reporting", E_ALL);
ini_set("display_errors", "on");
// surround the code with a try / catch
try {
  $var = [];
  // unknown key
  print $var["abcd"];
  // division by zero
  $var = 7 / 0;
  var_dump($var);
  // fixed terminal board
  $array = new \SplFixedArray(5);
  $array[1] = 2;
  $array[4] = "foo";
  // index outside the limits
  $array[5] = 8;
  // check
  print "ce message ne sera pas affiché\n";
} catch (\Throwable $ex) {
  // \Throwable is the interface implemented by most errors and exceptions
  // exception is displayed
  print "erreur, message : " . $ex->getMessage() . ", type : " . get_class($ex) . "\n";
}

    Comentarios

    • Este script es el que se presentó en el párrafo anterior. Sin embargo, ahora hemos envuelto el código de las líneas 8–19 —que podría provocar errores— en un bloque try/catch: si el código de las líneas 8–21 provoca (lanza) una excepción o un error, será gestionado por la cláusula catch de las líneas 22–26;
    • Línea 22: El parámetro de la cláusula [catch] es el tipo de excepción o error que se va a gestionar. Al especificar el tipo como [\Throwable] —que es una interfaz—, indicamos que queremos gestionar cualquier instancia de clase que implemente la interfaz [\Throwable]. Dado que todas las clases de error y excepción implementan esta interfaz, la cláusula [catch] aquí gestiona cualquier error o excepción encapsulado en una clase;
    • Línea 19: la instrucción que provoca el error y lanza la excepción. Tan pronto como se produce una excepción, el control pasa a la cláusula [catch]. Por lo tanto, el código que sigue a la línea 19 no se ejecutará;

    7.7. Parámetros de la cláusula [catch]

    Examinemos el siguiente script [exceptions-03.php]:

    
<?php
 
// all errors are displayed
ini_set("error_reporting", E_ALL);
ini_set("display_errors", "on");
 
// a fixed terminal board
$array = new \SplFixedArray(5);
try {
  // index outside the limits
  $array[5] = 8;
} catch (\Throwable $ex) {
  // error message display
  print "Erreur 1 : " . $ex->getMessage() . "\n";
}
 
try {
  // index outside the limits
  $array[5] = 8;
} catch (\Exception $ex) {
  // error message display
  print "Erreur 2 : " . $ex->getMessage() . "\n";
}
 
try {
  // index outside the limits
  $array[5] = 8;
} catch (\RuntimeException $ex) {
  // error message display
  print "Erreur 3 : " . $ex->getMessage() . "\n";
}
try {
  // division by 0
  intdiv(5, 0);
} catch (\Throwable $ex) {
  // error message display
  print "Erreur 4 : " . $ex->getMessage() . "\n";
}

try {
  // division by 0
  intdiv(5, 0);
} catch (\DivisionByzeroError $ex) {
  // error message display
  print "Erreur 5 : " . $ex->getMessage() . "\n";
}
 
try {
  // division by 0
  intdiv(5, 0);
} catch (\Error $ex) {
  // error message display
  print "Erreur 6 : " . $ex->getMessage() . "\n";
}
 
try {
  // division by 0
  intdiv(5, 0);
} catch (\Exception $ex) {
  // error message display
  print "Erreur 6 : " . $ex->getMessage() . "\n";
}

    Comentarios

    • líneas 8–31: tres formas diferentes de gestionar la excepción generada al utilizar un índice incorrecto con la clase [\SplFixedArray]. Hemos visto que este error genera una [RuntimeException];
      • línea 12: gestiona un error de tipo [\Throwable]. Esto es válido, ya que el tipo [RuntimeException] deriva del tipo [\Exception], que implementa la interfaz [\Throwable];
      • línea 20: gestiona un error de tipo [\Exception]. Esto es válido, ya que el tipo [RuntimeException] deriva del tipo [\Exception];
      • línea 28: gestiona un error de tipo [\RuntimeException]. Este es el método preferido, ya que es el tipo exacto de la excepción generada;
    • líneas 32–62: 4 formas diferentes de gestionar la excepción generada por la función [intdiv] al pasarle un divisor igual a 0. La función [intdiv(int $dividend, int $divisor): int] realiza la división entera $dividend / $divisor. Cuando el divisor es cero, se lanza la excepción [\DivisionByzeroError];
      • línea 35: capturamos cualquier error que implemente la interfaz [\Throwable]. Esto es válido;
      • línea 43: capturamos el tipo exacto del error: este es el método preferido;
      • línea 51: se captura el tipo [\Error]. Esto es válido, ya que la clase [DivisionByzeroError] extiende la clase [Error];
      • línea 59: se captura el tipo [\Exception]. Esto no es válido porque la clase [DivisionByzeroError] no tiene ninguna relación con la clase [\Exception];

    7.8. Cláusula [finally]

    La estructura try/catch puede tener un tercer elemento y convertirse en una estructura try/catch/finally. El código de la cláusula [finally] se ejecuta en los dos casos siguientes:

    • la cláusula [try] no lanza una excepción. En ese caso, se ejecuta en su totalidad y la ejecución del código continúa con la cláusula [finally], que se ejecuta en su totalidad;
    • la cláusula [try] lanza una excepción. A continuación, se ejecuta hasta la instrucción que lanza la excepción. La ejecución continúa entonces con la cláusula [catch], que se ejecuta en su totalidad. A continuación, la ejecución continúa con la cláusula [finally], que se ejecuta en su totalidad;

    Por último, el código del bloque [finally] siempre se ejecuta. Este escenario resulta útil en el siguiente caso:

    • en el bloque [try], el código ha adquirido recursos (archivos, bases de datos, conexiones de red, colas). Estos recursos suelen consumir mucha memoria. Por lo tanto, deben liberarse (lo que se suele denominar «cerrarse») lo antes posible;
    • Si se han adquirido recursos en el bloque [try], su liberación debe colocarse en el bloque [finally]. Esto garantiza que, en todos los casos (se produzca o no un error), los recursos adquiridos se devuelvan al sistema;

    El siguiente script [examples/exceptions/exceptions-04.php] muestra cómo funciona la cláusula [finally] en diversas situaciones:

    
<?php
 
// or create an exception instance
$e = new \Exception("Erreur…");    
var_dump($e);
 
// first test
try {
  print "Premier test\n";
  throw $e;
} catch (\Exception $ex1) {
  print $ex1->getMessage() . "\n";
} finally {
  print "Terminé\n";
}

// second test
try {
  print "Second test\n";
} catch (\Exception $ex1) {
  print $ex1->getMessage() . "\n";
} finally {
  print "Terminé\n";
}
 
// third test
try {
  print "Troisième test\n";
  return;
} catch (\Exception $ex1) {
  print $ex1->getMessage() . "\n";
} finally {
  print "Terminé\n";
}

    Comentarios del código

    • línea 4: $e es una instancia de la clase predefinida [\Exception]. La lanzaremos en varios lugares;
    • líneas 8–15: la excepción $e se lanza en el bloque [try] (línea 10);
    • línea 11: se captura la excepción [\Exception] y su mensaje de error se escribe en la consola;
    • líneas 13–15: la cláusula [finally] imprime un mensaje. Según lo mencionado anteriormente, este mensaje siempre debería imprimirse, independientemente de si hay un error en el bloque [try];
    • líneas 18–24: no hay ningún error en el [try]. Aquí también deberíamos entrar en el bloque [finally];
    • líneas 27-34: hay una instrucción [return] en el bloque «try» y no se produce ningún error. Cabría preguntarse, entonces, si se ejecutará la cláusula [finally]. La ejecución demuestra que sí;

    7.9. Creación de tus propias clases de excepción

    En un proyecto de cierta envergadura, resulta útil diferenciar entre distintos errores encapsulándolos en diferentes clases de excepción. En el script anterior, vimos que cualquier excepción podía ser capturada mediante una cláusula [catch (\Throwable]. Esto se recomienda si no se sabe de qué error se trata y el tratamiento es el mismo para todos los errores. A veces es así, pero a menudo es necesario adaptar el tratamiento al tipo exacto de error. Por lo tanto, debes distinguir entre los errores.

    Examinemos el siguiente script [exceptions-06.php]:

    
<?php
 
// we define our own family of exceptions
class Exception1 extends \RuntimeException {
  
}
 
class Exception2 extends \RuntimeException {
  
}
 
// or use our exceptions
$e1 = new Exception1("Erreur1…");
var_dump($e1);
$e2 = new Exception2("Erreur2…");
var_dump($e2);
 
// first test
print ("premier test\n");
try {
  // throw an Exception1 type
  throw $e1;
} catch (Exception1 $ex1) {
  print "Exception 1" . "\n";
  print $ex1->getMessage() . "\n";
} catch (Exception2 $ex2) {
  print "Exception 2" . "\n";
  print $ex2->getMessage() . "\n";
}
 
// second test
print ("second test\n");
try {
  // throw an Exception2 type
  throw $e2;
} catch (Exception1 $ex1) {
  print "Exception 1" . "\n";
  print $ex1->getMessage() . "\n";
} catch (Exception2 $ex2) {
  print "Exception 2" . "\n";
  print $ex2->getMessage() . "\n";
}
 
// third test
print ("troisième test\n");
try {
  // throw an Exception1 type
  throw $e1;
} catch (Exception1 | Exception2 $ex) {
  print "Exception 1 ou 2" . "\n";
  print $ex->getMessage() . "\n";
}
 
// fourth test
print ("quatrième test\n");
try {
  // throw an Exception2 type
  throw $e2;
} catch (Exception1 | Exception2 $ex) {
  print "Exception 1 ou 2" . "\n";
  print $ex->getMessage() . "\n";
}

    Comentarios

    • líneas 4-10: definimos dos clases, [Exception1] y [Exception2], ambas derivadas de la clase predefinida [\RuntimeException]. El cuerpo de estas clases está vacío. En otras palabras, solo las utilizamos para especificar sus tipos: es precisamente por ar tipos diferentes por lo que podremos distinguir entre estas dos excepciones en las cláusulas [catch];
    • líneas 13–16: definimos dos variables, $e1 y $e2, con los tipos [Exception1] y [Exception2], respectivamente;
    • líneas 20-29: tenemos una estructura try/catch/catch. Esto nos permite gestionar diferentes tipos de excepciones con diferentes cláusulas [catch];
    • línea 23: captura excepciones de tipo [Exception1];
    • línea 26: captura excepciones de tipo [Exception2];
    • línea 49: captura excepciones de tipo [Exception1] o (|) [Exception2];

    7.10. Re-lanzamiento de una excepción

    Una excepción se puede lanzar varias veces, como se muestra en el siguiente script [exceptions-07.php]:

    
<?php
 
try {
  try {
    // throw an exception
    throw new \Exception("test");
  } catch (\Exception $ex) {
    // the intercepted exception is re-launched
    throw $ex;
  } finally {
    // we'll make it to the finally
    print "finally 1\n";
  }
} catch (\Exception $ex2) {
  // the initial exception is recovered
  print $ex2->getMessage() . " dans try / catch / finally externe\n";
} finally {
  // we'll make it to the finally
  print "finally 2\n";
}

    Comentarios

    • línea 6: lanzamos una excepción;
    • línea 7: la capturamos;
    • línea 9: la volvemos a lanzar. A continuación, pasa por el bloque try/catch/finally del nivel superior;
    • línea 14: se captura de nuevo;
    • líneas 10–12: la ejecución muestra que, incluso después del [throw] de la línea 9, el control fluye efectivamente hacia la cláusula [finally] del bloque try/catch/finally;

Para propagar un error de vuelta al código que llama al método M, encapsularemos estas excepciones dentro del tipo [Exception1], que lanzaremos. Esto garantiza que la información contenida en la excepción encapsulada —que fue la causa original del error— no se pierda;
